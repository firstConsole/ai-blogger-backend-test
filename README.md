# AI-блогер

[![CI](https://github.com/firstConsole/ai-blogger-backend-test/actions/workflows/ci.yml/badge.svg)](https://github.com/firstConsole/ai-blogger-backend-test/actions/workflows/ci.yml)

Автономный контент-конвейер для Telegram-канала: собирает темы из RSS и поиска,
пишет черновик, прогоняет его через критика, рисует картинку, отдаёт человеку на
подтверждение и публикует по расписанию. Потом снимает статистику и подмешивает
удачные темы обратно в промпт.

Проект настраивается под любой канал: тон, редполитика, расписание, источники и
даже выбор моделей задаются для каждого канала отдельно и хранятся в базе, а не
в коде.

## Стек

| Слой | Что используется | Почему |
|---|---|---|
| Язык | Python 3.13, asyncio | нагрузка целиком I/O-bound |
| Очередь задач | TaskIq + Redis | асинхронная из коробки, мало кода |
| База | PostgreSQL 18 | контент-план, метрики, настройки каналов |
| Черновик | Claude Sonnet 5 | качество текста на длинном контексте |
| Критик | GPT 5.4 nano | дешёвая вторая пара глаз перед публикацией |
| Картинки | GPT Image 2 | для блога качество картинки решает |
| Источники тем | RSS + Brave Search | плюс ручное добавление через бота |
| Дедупликация | Sentence-Transformers | эмбеддинги считаются локально, стоят $0 |
| Публикация | aiogram 3 | Bot API |
| Аналитика | Telethon (MTProto) + Bot API | просмотры Bot API не отдаёт, нужен MTProto |
| Хранилище картинок | S3-совместимое (Cloudflare R2) | 10 ГБ бесплатно |
| Наблюдаемость | structlog, Prometheus, Grafana | структурные логи и дашборды |

## Быстрый старт

Нужны Python 3.13, [Poetry](https://python-poetry.org/) 2.x и Docker.

```bash
make install     # зависимости и git-хуки
make env         # создаст .env из .env.example
```

Дальше откройте `.env` и заполните обязательные значения — какие именно, написано
в самом файле. Минимум, без которого проект не поднимется:

| Переменная | Где взять |
|---|---|
| `TELEGRAM__BOT_TOKEN` | [@BotFather](https://t.me/BotFather) |
| `TELEGRAM__ADMIN_CHAT_ID` | id чата, куда приходят посты на подтверждение |
| `POSTGRES__PASSWORD`, `REDIS__PASSWORD` | придумайте: `openssl rand -hex 24` |
| `LLM__ANTHROPIC_API_KEY`, `LLM__OPENAI_API_KEY` | консоли провайдеров |
| `STORAGE__*` | доступы к бакету R2 или другому S3 |
| `SECURITY__SECRETS_ENCRYPTION_KEY` | `openssl rand -base64 48`, минимум 32 байта |

```bash
make up          # Postgres и Redis, команда ждёт, пока оба станут healthy
make check       # линтер, типы, тесты
```

Приложение на время разработки запускается на хосте, а не в compose — так работают
отладчик и автоперезапуск. Готовый образ собирается отдельно: `make build`.

## Команды

`make` без аргументов покажет список. Самое ходовое:

| Команда | Что делает |
|---|---|
| `make check` | линтер, типы и тесты — ровно то же, что гоняет CI |
| `make format` | отформатировать и починить, что чинится само |
| `make up` / `make down` | поднять и остановить стенд |
| `make destroy` | остановить и стереть данные — когда нужен чистый старт |
| `make build` | собрать рабочий образ |

Перед коммитом автоматически отрабатывают быстрые проверки, перед `git push` —
`mypy` и тесты. Хуки ставятся командой `make install`.

## Структура

Проект разложен по Clean Architecture. Стрелки зависимостей смотрят только
внутрь, к домену; за этим следит
[тест-страж](tests/architecture/test_layer_boundaries.py), а не договорённость.

```
src/ai_blogger/
├── domain/          правила предметной области, ноль зависимостей
├── application/     сценарии и порты во внешний мир
├── infrastructure/  реализации портов: база, LLM, Telegram, хранилище, логи
├── presentation/    точки входа: админ-бот и фоновые задачи
└── bootstrap/       composition root: конфигурация и сборка приложения
```

Каждый слой начинается с описания того, что в него можно класть и чего нельзя.

## Конфигурация

Настройки разделены намеренно, и это разделение важнее, чем кажется:

* **`.env`** — параметры установки: адреса баз, ключи провайдеров, лимиты. Их
  знает администратор сервера. В репозиторий не попадают никогда.
* **база данных** — настройки канала: тон, редполитика, расписание, источники,
  модели. Их меняет владелец канала прямо из бота, без передеплоя.

Правило: если значение нужно менять без выкладки — ему не место в `.env`.

## Безопасность

* `.env` закрыт `.gitignore` и отдельным pre-commit хуком; в репозитории живёт
  только `.env.example` с пустыми значениями. Ещё коммиты просматривает `gitleaks`.
* Все секреты в конфигурации — `SecretStr`. Логи проходят через процессор,
  который вырезает токены, ключи и пароли в DSN, — включая записи чужих
  библиотек. Ошибка загрузки конфигурации сообщает имя переменной, но не значение.
* В `production` приложение не поднимется с `debug=true`, шаблонными секретами
  или неструктурированными логами — лучше не подняться, чем подняться дырявым.
* Рабочий образ работает от непривилегированного пользователя, без setuid-бинарников
  и без возможности переписать собственный код. Сервисы стенда запущены с
  `cap_drop: ALL` и файловой системой только на чтение.
* Осторожно с `docker compose config` и `docker inspect`: они печатают значения
  переменных. Такой вывод нельзя вставлять в задачи, PR и чаты.
